The candidate follows the frozen rule's relevant constraint: distinct historically observed recovery, model, metadata and phase changes coexist, yet one selected local seam retains the cohesive ordered algorithm. Keeping the old unit would avoid the added call/interface; keeping set-phase internals unchanged is an especially strong counterexample to further splitting because their existing seam already suffices. Actual costs are eleven explicit inputs, a second function contract, an additional async handoff and slightly more total lexical surface. The same query closure and client are both passed; they remain coupled to the dedicated transaction by caller discipline, not a new type-level guarantee. There is no measured runtime, allocation, developer-time or defect-rate benefit. The added handoff does not change awaited database command order in the reviewed flow.

Limited ongoing use is warranted **conditionally on regression gates** as a reasoning procedure for newly observed change pressure in Velvet, with explicit keep alternatives, invariant maps and bounded probes. This single extraction supports neither mandatory size thresholds nor automatic architectural decomposition, nor generalization to Alder. Reopen if ordinary work expands the interface repeatedly, requires coordinated model/lifecycle edits, or produces regressions.
