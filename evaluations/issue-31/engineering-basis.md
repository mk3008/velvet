# Engineering basis and local inference

Sources checked 2026-09-14. These are precedents for reasoning, not empirical proof
that this Velvet change saves developer time. No source prescribes our trigger,
module names, automatic action policy, or evaluation threshold.

| Material criterion | External engineering knowledge / precedent | Velvet evidence | Agent judgment / assumption |

| Organize around observed change reasons | D. L. Parnas, *On the criteria to be used in decomposing systems into modules*, 1971 technical report / 1972 CACM paper, especially comparison of decompositions and criteria: [primary paper](https://prl.khoury.northeastern.edu/img/p-tr-1971.pdf). Hiding design decisions can localize their changes; processing steps alone are insufficient criteria. | Durable Run repair 6ffab6f; mutable lifecycle fbfe73e; row/routine 6e89908; set phases ff0cbbd changed different concerns in one function. | A lifecycle/work seam is worth testing now; the history is evidence of reasons, not a statistical coupling model. |
| Consider divergent change but also the inverse cost | Fowler and Beck, *Refactoring*, 2nd ed., publisher excerpts: [Divergent Change](https://www.informit.com/articles/article.aspx?p=2952392&seqNum=7), [Shotgun Surgery](https://www.informit.com/articles/article.aspx?p=2952392&seqNum=8). Different contexts concentrated in one unit and one change dispersed across units are different maintenance problems. | Shared Work/Processing/Active/Lineage decisions are coordinated in the row loop; both routes finalize the same Run. | Do not mandate per-model splitting. Count extra edit sites and invariant owners, including cross-cutting tasks; a larger cohesive function may be preferable. |
| A smell triggers investigation, not a verdict | Fowler, [Code Smell](https://martinfowler.com/bliki/CodeSmell.html), 2006: a surface indication can be harmless; investigate context. | Decision 0007 retained the execution boundary for useful transaction ownership. Insert-only simplification 8bb20a2 removed special cases. | No LOC cutoff; keeping or simplifying is a valid output. Reopen on changed evidence, not a timer or size threshold. |
| Preserve observable behavior and test the cost/benefit | Fowler, [Definition of Refactoring](https://martinfowler.com/bliki/DefinitionOfRefactoring.html), 2004. Internal restructuring aims at easier comprehension/modification while preserving observable behavior. | Existing PostgreSQL fault injection, row/routine suites, set-phase parity and lost-COMMIT tests; fixed SQL and stored-SQL trust boundaries. | Preserve ordered work text and recovery logic, run existing DB gates, measure a limited inspection/coordination proxy. Passing tests is regression evidence, not a proof of semantic equivalence. |
| Automatic implementation versus proposal | No claim of a universal literature-derived authorization formula. | AGENTS.md permits AI-owned internal structure, requires Business Design, decision records, PostgreSQL verification and human-owned merge. | Reversible internal edits can proceed for review; uncertain meaning, externally consequential action or insufficient safety evidence requires proposal/escalation. |
| Small independent replication and bounded stopping | Evaluation design is our judgment, not a validated benchmark. | Issue 31 asks for independent applications; AGENTS.md prioritizes reasoning-led bounded evaluation. | Two isolated-context baseline applications test compatible decisions; task probes and semantic review test this candidate. Do not generalize to unseen repositories or claim quantified labor savings. |
