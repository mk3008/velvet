# Ownership cue: one follow-up, target candidate still not generated

In response to [comment 5673099006](https://github.com/mk3008/velvet/pull/36#issuecomment-5673099006),
we made one conditional candidate-generation addition to Decision 0016 and ran
exactly one new fresh context. The [original negative result](../runs/intake.md)
is unchanged. [Protocol](protocol.md), [patch](guidance.patch), [input manifest](input.json)
[raw new response](response.md) and [result provenance](result.json) preserve the comparison.

## Why change guidance

The author had a supported removable-forwarder candidate that the first ordinary
application did not generate. A single omission does not prove general bias, but
it is evidence of a local gap worth one small intervention. The initial decision
to make no guidance change required too much general evidence before testing a
cheap, reversible clarification of the existing KISS principle.

The added cue asks whether a reconsidered boundary still owns independent policy,
invariant, change or verification responsibility. Prior adoption is not an
exemption. When none remains and crossing the seam repeats the same checks, a
plausible inline/consolidation/removal/redraw can be considered alongside extraction.
It neither prescribes removal nor requires every direction on every task.
AGENTS already points to 0016, so no duplicate instruction was added there.

## Frozen comparison and observation

Both agents received the same ordinary task text. The new isolated checkout
contains baseline `fcda11b` source/tests/history, including both forwarders, plus
only the 0016 patch. No prior answer, PR diff, Issue 34 report or owner comment
was available in its files or visible Git refs. The agent itself reports reading
the modified Decision diff and committed version; this is not a blinded treatment
or evidence that it used only the new wording. No hints or follow-up were sent.
The application runs used inherited model settings without overrides; no complete
per-tool transcript or internal-attention measurement is retained.

The new response does mention runtime subtraction (repeated parsing) and rejects
mapping inlining. Those observations are retained, not erased to force a binary
story. It does not offer the duplicate-parse removal as a supported maintenance
candidate, and does not identify the forwarder contract as removable. Under the
frozen requirement of a concrete maintenance-cost reason, this is **no demonstrated
improvement in generating the warranted forwarder/subtractive candidate**.
Cast removal alone is not relabeled as runtime boundary removal.

## Disposition and limits

Keep the small ownership cue as an explicit, conditional reasoning aid consistent
with KISS, with **effectiveness unestablished**. Its adoption is a low-cost guidance
clarification justified by the observed omission, not a claim that this experiment
validated improved agent behavior. Keeping a boundary may still have naming or
navigation value; absence of independent ownership alone does not prove removal
has net benefit. Existing keep/change evaluation, timing and gates still decide.

Stop now, including if another wording might produce the preferred answer. The
owner authorized one new run, and it is complete. No matrix, stronger steering,
new runtime change, checklist, recurring audit or Alder modification follows.
Mapping KEEP, the reviewed two-forwarder removal, and A2/B2 remain unchanged.

One observation per guidance condition cannot separate model variability, task
framing and guidance effect, estimate success rates or generalize to unseen
boundaries. The neutral task asked for a justified improvement, not exhaustive
alternatives; choosing a smaller type fix remains a possible explanation. We have
not proved why the candidate was omitted or that the cue cannot help elsewhere.
A future natural maintenance task can supply evidence; none is scheduled here.
